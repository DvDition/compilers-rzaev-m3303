## LAB 1

Задача A. Do It Yourself
Легенда: Минимальное задание для зачёта 
первой лабораторной. Вы проходите весь 
путь программы от исходного текста до 
исполняемого файла, останавливаясь на 
каждом этапе и фиксируя, что с ней 
происходит.
Требования к окружению: Linux, WSL или 
godbolt.org. Формат сдачи: Текстовый файл 
с ответами на вопросы и выводом команд.
Создайте файл simple.cpp со следующим 
содержимым:

```cpp
#include <cstdio>


int global_counter = 0;

const int MAGIC = 42;


int square(int x) {

    return x * x;

}


int sum_of_squares(int a, int b)
{

    return square(a) + 
square(b);

}


void bump_counter() {

    global_counter++;

}


int main() {

    int result = 
sum_of_squares(3, 4);

    bump_counter();

    printf("Result: %d, Counter:
%d, Magic: %d\n", result, 
global_counter, MAGIC);

    return 0;

}
```

Пройдите по всем этапам сборки вручную. 
На каждом этапе выполните необходимые 
команды и ответьте на вопросы.
Вопросы:
1.
Сколько строк было в исходном файле и 
сколько стало в .i?
2.
Найдите в simple.i функцию main. Что 
находится над ней в файле? Почему там 
так много строк?
3.
Найдите в simple.i строку "Result: 
%d, Counter: %d, Magic: %d\n". Где 
она оказалась и что с ней сделал 
препроцессор?
Подсказка: используйте -S, -masm=intel 
и флаги оптимизации -O0 и -O2.
Вопросы: 4. Сравните размеры файлов -O0 
и -O2. Во сколько раз оптимизированный 
код короче? 5. Откройте файл, полученный 
после сборки без оптимизации. Найдите 
метку square:. Какие инструкции там 
используются для умножения? 6. Найдите 
метку main:. Какие регистры используются 
для передачи аргументов в вызов 
sum_of_squares? Как это связано с 
соглашениями о вызовах? 7. Во втором 
файле (с -O2) функция square скорее всего 
исчезла. Почему?
Подсказка:
bash
g++ -c simple.cpp -o simple.o

nm simple.o

size simple.o
Вопросы: 8. Почему MAGIC имеет тип R 
(read-only data), а не D (data)? 9. Что 
показывает команда size? Какие секции 
занимают больше всего места и почему?
Вопросы: 10. Какой результат вывела 
программа?
